## 1. Benchmark Overview & Methodology

The OWASP Lab benchmark provides a repeatable, local empirical ground truth for measuring Bounty Hunter's detection and verification capabilities. Every scenario is scored against its known ground-truth vulnerability status.

The scoring model evaluates:
- **True Positive (TP):** Ground-truth vulnerable scenario accurately identified and verified.
- **False Positive (FP):** Non-vulnerable scenario erroneously reported as vulnerable.
- **True Negative (TN):** Non-vulnerable scenario correctly verified as secure.
- **False Negative (FN):** Ground-truth vulnerable scenario missed by the testing engines.

## 4. Key Performance Drivers in Phase 15.1

1. **Differential Dual-Token Verification (A01 Broken Access Control):**
   - In Phase 8, requesting `/api/documents/1001` with User B's token returned HTTP 200, which triggered a false positive on protected endpoints because the endpoint returned an error object formatted as HTTP 200 (`{"status": "error", "code": 403}`).
   - Phase 15.1 requires User A vs. User B payload delta verification. Only when User B receives User A's actual tenant-isolated data is an IDOR verified.

2. **Semantic Context in SAST (Semgrep vs. Regex):**
   - Replaced naive regex string searching with Semgrep AST matching, eliminating false positives on sanitized SQL statements and parameterized queries.

3. **Multi-Engine Consensus:**
   - DAST hypotheses generated by Nuclei or Dalfox require correlation with runtime differential replay or AST confirmation before escalating to `VERIFIED`.
