Module 3: Differential Authorization Testing Engine
Broken Object Level Authorization (BOLA/IDOR) is the most critical logic flaw in modern APIs. Rather than fuzzing random characters, a differential engine evaluates authorization boundaries between distinct permission contexts:
1. Dual-Context Provisioning: The runner accepts two valid authentication contexts:
   - Context A: Low-privilege user or Tenant A.
   - Context B: Target user or Tenant B.
2. Object Identification: When an endpoint contains an identifiable resource reference (UUIDs, sequential integers, account IDs):
   - Send the request under Context A for Resource A to establish a baseline response (status, headers, structural schema).
   - Replay the request against Resource A using Context B’s credentials.
3. Differential Analysis: Compare the execution outcomes:
   - Status Codes: Does Context B receive a 200 OK instead of 401 Unauthorized or 403 Forbidden?
   - Body Structure & Content: Does the response return object data that matches Context A's schema rather than an error payload?
   - Data Reflection: Flag instances where sensitive tenant data is returned across authorization boundaries.
Module 4: Proxy Integration (Burp Suite / Caido Alignment)
Automated scanners miss contextual business logic (such as workflow bypasses in checkout or multi-step registrations). The automation must seamlessly feed manual analysis environments:
- Proxy Forwarding: All requests executed by your engine should optionally route through a local proxy listener (--proxy [http://127.0.0.1:8080](http://127.0.0.1:8080)).
- Sitemap Population: Import the generated OpenAPI specification or crawler sitemap directly into Burp Suite so the researcher can immediately begin manual session inspection without repeating the crawl.
Module 5: Noise Reduction & Confidence Scoring
A primary reason bug reports are rejected is the prevalence of non-exploitable false positives or duplicate findings.
- WAF/CDN Fingerprinting: Detect edge behaviors (Cloudflare, Akamai, CloudFront) to prevent reporting generic CDN error pages (403, 502) as application-level vulnerabilities.
- Dynamic Content Normalization: Strip dynamic timestamps, CSRF tokens, and nonce values before calculating diffs between HTTP responses to eliminate false variance.
- Evidence Packaging: Automatically generate a reproducible cURL command, raw HTTP request/response log, and exact parameter location for human verification.
