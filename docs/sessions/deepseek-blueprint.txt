模块一：JS AST 提取——把前端 bundle 变成结构化端点

在你的 Discovery 模块中，流程是：

从 state 中取出属于目标 host 的 .js 和 .js.map URL。

下载后喂给 jstangle（可以通过 CLI 或库调用）。

模块二：差分授权测试——唯一值得自动化的高价值逻辑
BOLA/IDOR 仍然是 OWASP API 风险的第一名，而且一项针对 107 个 bug bounty 披露的分类研究发现，41.7% 的确认 BOLA 案例是状态变更操作（修改/删除他人的对象），而不是只读泄露。只测“换 id 看能不能读”覆盖的是较小的一半。

执行逻辑（直接可实现的算法）
Sentinel 项目中的 bola_tester.py 给出了最小可行结构：

text
对于 state 中每一个 endpoint:
    如果 endpoint 没有 object_ref 参数: 跳过
    如果 endpoint 的 method 不在 {GET, PUT, PATCH, DELETE} 中: 跳过

    # Step 1: 以 Owner 身份建立基线
    resp_owner = request(endpoint, session=UserA, resource_id=从UserA收集到的id)
    如果 resp_owner.status >= 400: 跳过（Owner 自己都访问不了，无法建立基线）

    # Step 2: 以 Attacker 身份重放完全相同的请求
    resp_attacker = request(endpoint, session=UserB, resource_id=同一个id)

    # Step 3: 差分
    if resp_attacker.status < 400:
        similarity = compare(resp_owner.body, resp_attacker.body)
        if similarity > 0.5:   # 阈值可调
            写入 test_attempts, anomaly_score = similarity
            如果 method != GET:  # 状态变更操作，优先级更高

关键细节：resource_id 不能随机生成。你需要先从 User A 的会话中收集真实的、属于 A 的对象 ID。可以在差分测试之前加一个轻量的“对象发现”步骤：用 User A 遍历已知端点，提取响应中的 id、uuid、*_id 字段，存入一个 known_object_refs 表，关联到 session_label = UserA。

差分引擎的输出不直接是 finding。它写入 test_attempts 中的 anomaly_score。只有当 anomaly_score 超过阈值，并且 Orchestrator 判断该端点所属的 host 在当前 scope 内、cdn_waf 特征不是已知的全局 403 页面时，才触发验证。

模块三：验证与反馈——对抗幻觉的唯一手段
差分测试会产生假阳性：CDN 对两个用户都返回同一个通用 200 页面、应用返回了结构相同但内容为空的 JSON、状态变更请求实际上被下游逻辑静默拒绝了但前端展示成功。自动化产生的异常必须经过独立验证，才能成为可提交的 finding。

验证层不应该是另一个无状态扫描器，而是一个基于证据的裁决器：

规则验证（优先） ：如果 resp_attacker.status 是 2xx，但 resp_attacker.body 中不包含从 User A 基线中提取的任何敏感字段值（email、name、balance、order total），则驳回。如果包含，则通过规则验证。

AI 验证（用于规则无法裁决的灰色地带） ：把双方的归一化请求 + 响应片段（剥离动态 token、时间戳）交给 LLM，提问：“Attacker 的响应是否包含 Owner 的私有数据，或者是否执行了对 Owner 对象的修改？给出 yes/no 和理由。” AI 在这里的角色是判断语义等价性，而不是生成 payload。RedAgent 的 “Dynamic Test Iteration Engine with Backtracking” 思路可以用在这里：如果 AI 认为证据不足，它可以建议一个具体的补充验证请求（例如，换一个字段、加一个 header），而不是直接输出“可能有洞”。

验证结果写回 findings：verified_by = "rule" 或 "ai"，confidence 根据验证强度赋值。只有 verified_by 非空的条目才出现在最终导出中。

这套三层结构（规则优先 → AI 语义补充 → 证据落库）直接回应了你之前关心的“AI 幻觉”问题。AI 不决定有没有漏洞，AI 只帮助判断“这两个响应在语义上是否等价”。
