## 2. Detailed Technical Root Causes & Fixes

### DEF-01: Approval Command `now_iso` NameError
- **Root Cause:** When running `bb h1 approve --program <prog> --target <target>`, the CLI handler called `now_iso()` on lines 1061 and 1102, but `now_iso` was omitted from `from bb.config import (...)`.
- **Fix:** Added `now_iso` to the imports from `bb.config` in `bb/cli.py`.
- **Verification:** Unit test `test_now_iso_generates_valid_utc_timestamp` and `test_successful_approval_workflow`.

### DEF-02: `ProgramAuthorizationBrief` Extra Field Deserialization Crash
- **Root Cause:** Real brief files generated by `BriefGenerator` include analytical keys such as `path_exclusions`, `scope_conflicts`, `rate_limit_source`, and `human_review_notes`. Calling `ProgramAuthorizationBrief(**data)` raised `TypeError: unexpected keyword argument`.
- **Fix:** Implemented `ProgramAuthorizationBrief.from_dict(cls, data: dict[str, Any])` in `bb/h1.py` which filters keyword arguments against dataclass field names and safely parses enums.
- **Verification:** Unit test `test_brief_from_dict_handles_extra_fields`.

### DEF-03: Finding Store & Class NameError in Scenario Execution
- **Root Cause:** In `bb/cli.py:661`, `Finding` was referenced without being imported from `bb.models`. Furthermore, line 672 invoked `store.save_finding(args.program, finding)`, but `Store` defined `add_finding(self, finding, run_id=None)`.
- **Fix:** Imported `Finding` in `bb/cli.py`, changed call to `store.add_finding(finding, run_id=getattr(args, "program", None))`, and added a backwards-compatible `save_finding` wrapper to `Store` in `bb/store.py`.

### DEF-04: WAF Probing Method Name Mismatch
- **Root Cause:** `cmd_waf` called `waf.probe_url` and `waf.format_report`. However, `bb/waf.py` defined `probe` and `format_probe`.
- **Fix:** Updated `cmd_waf` to call `waf.probe` and `waf.format_probe`, and added backward-compatibility aliases in `bb/waf.py`.

### DEF-05: Missing `apex_domains` on Scope
- **Root Cause:** CLI modules invoked `scope.apex_domains()` to discover eligible apex domains for reconnaissance, but `Scope` only implemented `in_scope_patterns`.
- **Fix:** Implemented `apex_domains(self) -> list[str]` on `Scope` in `bb/scope.py`, extracting all non-wildcard, non-CIDR hostname rules with deduplication.

### DEF-07 & DEF-08: Automation Route Normalization & Role Login Calls
- **Root Cause:** `bb/auto.py:174` passed 6 arguments to `Store.record_route()`, which accepts `(run_id, url, method="GET", source="")`. Line 199 called `login_roles(config, scope, ...)` whereas `login_roles` requires `(client: ScopedClient, config: dict, log=print)`.
- **Fix:** In `bb/auto.py:174`, called `self.store.record_route(self.run_id, u, method=m, source="discovery")`. Initialized `ScopedClient` prior to authentication and passed `(client, self.cfg.accounts, log=self.log)`. Applied equivalent fix to `bb/orchestrator/controller.py`.

### DEF-09: IntelligenceStore `query_text` Method
- **Root Cause:** `ContinuousScheduler` invoked `self.intel_engine.store.query_text(self.profile.program_id, limit=10)`, but `IntelligenceStore` named the method `search()`.
- **Fix:** Added `query_text(self, query: str, limit: int = 50)` method forwarding directly to `self.search(query=query, limit=limit)`.

### DEF-10: Burp XML Export Missing `Exchange`
- **Root Cause:** `bb/ui.py:617` constructed `Exchange(...)` from SQLite rows, but `Exchange` was not imported from `bb.models`.
- **Fix:** Added `Exchange` to `from bb.models import Exchange, sev_rank` in `bb/ui.py`.

### DEF-11: LLM Type Annotations & Abstract Provider
- **Root Cause:** Multiple modules (`bb/analyze.py`, `bb/kb.py`, `bb/report.py`) annotated `llm: Ollama | None = None` without importing `Ollama` after refactoring.
- **Fix:** Defined `LLMProvider = Ollama | OpenAICompatible` in `bb/llm.py` and updated type hints across modules to `llm: LLMProvider | None = None`.

### DEF-15: Builtin `any` Typing
- **Root Cause:** `bb/programs/ai_development_intel.py`, `bb/intel/rule_registry.py`, and `bb/intel/vector_store.py` used `Dict[str, any]` referencing the Python builtin function `any`.
- **Fix:** Replaced with `typing.Any`.

### DEF-16: Windows CP1252 Subprocess Encoding
- **Root Cause:** `subprocess.run(..., text=True)` without explicit encoding uses the host default ANSI code page on Windows (`cp1252`), which crashes with `UnicodeDecodeError` when external CLI tools (Semgrep, Trivy, Dalfox, TruffleHog) output UTF-8 glyphs or box-drawing characters.
- **Fix:** Added `encoding="utf-8", errors="replace"` to all text subprocess calls across `bb/engines/` and `bb/intel/rule_validation.py`.

### DEF-17: Comprehensive Scope Conflict & Target Approval Gate
- **Root Cause:** Approval CLI command previously permitted approving targets that had conflicting policy prohibitions (e.g. subdomains forbidden by policy text), paths explicitly excluded (e.g. `/web-security`), or briefs generated against stale scope fingerprints.
- **Fix:** Enhanced `bb/cli.py:cmd_h1` approval handler:
  1. Enforced target presence.
  2. Verified live scope permission via `scope.is_in_scope(target)`.
  3. Verified brief scope fingerprint matches live scope (`brief_scope_fp == scope.fingerprint`).
  4. Blocked targets matching any `scope_conflicts` recorded in the brief.
  5. Blocked targets whose URL path matches any entry in `path_exclusions`.
  6. Blocked targets matching structured asset entries with `INELIGIBLE` or `UNKNOWN` submission status.
- **Verification:** 10 dedicated regression tests in `tests/test_h1_approval_workflow.py`.
